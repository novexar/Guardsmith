# コーディング規約 — {{PROJECT_NAME}}

## 全PJ共通(Novexar 標準)
- **不変性**: 既存オブジェクトを破壊的変更せず、新しいコピーを返す。
  - **適用範囲**: 自分が書くドメインロジック・状態の受け渡しに適用する。
  - **例外**: 状態管理ライブラリ / ORM エンティティ / ストリーム・バッファ処理など、**スタックの慣習が破壊的更新を前提とする箇所**は例外とする。該当するものは下の「スタック固有」節に具体名で明示し、それ以外では例外にしない。
- **小さなファイル/関数(目安)**: 関数 50 行、ファイル 800 行(200–400 行が目安)、ネスト 4。
  - これは**可読性の目安であり、機械的な閾値ではない**。超えたこと自体を欠陥として扱わない。
  - **行数を合わせるためだけの分割や、行数超過だけを理由にした差戻しは禁止**。分割の理由は「責務が混ざっている」「テストしづらい」など中身で述べる。
  - 機械検査は行わない。
- **明示的なエラーハンドリング**: 握りつぶし禁止。境界(API 入力・DB・外部 API)で必ず入力検証。
- **秘密情報のハードコード禁止**: 環境変数 / Secrets 管理を使用。
- **デバッグ出力の残置禁止**: `console.log` / `print` のコミット禁止。
- **テスト(変更種別に応じる)**:
  - コード変更: TDD(RED→GREEN→REFACTOR)、カバレッジ 80%+、Unit / Integration / E2E の 3 層。
  - 文書・コメントのみの変更: テスト作成は不要(既存テストがグリーンであることだけ確認する)。
  - 設定・依存の変更: 影響する経路の既存テストと、ビルド/起動の確認をもって検証とする。
  - カバレッジ 80% は「競合・部分失敗・境界」の検証の代替にならない(`.claude/agents/qa-engineer.md` の検証条件を参照)。
