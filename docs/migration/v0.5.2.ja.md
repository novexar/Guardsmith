# v0.5.2 移行ガイド — 既存プロジェクトの差分適用チェックリスト

[English](v0.5.2.md) | **日本語**

対象: v0.5.1 標準で運用中のプロジェクト。
それ以前から移行する場合は、先に [v0.5.0](v0.5.0.ja.md) / [v0.5.1](v0.5.1.ja.md) の移行ガイドを
適用してから本ガイドに進む。

> **まず前提**: リモート参照はタグ固定のため、**何もしなくても壊れない**。追随は任意。

v0.5.1 からの差分は走査範囲。`guard lint` / `guard sync` が `.gitignore` に追従するようになり、
ポリシーにトップレベル `ignore` キーが増えた。

## チェックリスト

### 1. extends タグを v0.5.2 へ上げる

```yaml
extends:
  - github:novexar/guardsmith//presets/baseline.yaml@v0.5.2 # ← @v0.5.1 から変更
```

baseline の `security/no-secrets-in-context` が `.claude/worktrees/**` を明示除外するため、
旧 CLI のままでもエージェント worktree による誤検知が止まる。

- [ ] extends のタグを `@v0.5.2` に変更した

### 2. CLI を 0.4.0 へ上げる

```bash
npx @guardsmith/cli@0.4.0 lint
```

Action を使っている場合は `cli-version: "0.4.0"` を指定するか、
`uses: novexar/Guardsmith@v0.5.2`(既定が 0.4.0)へ更新する。

0.4.0 から、走査対象は「**コミットされうるファイル**」に限定される。`.gitignore`(入れ子の
`.gitignore` も)に追従し、`.git/` は常に除外する。

8 種の check のうち 7 種は glob でファイルを列挙するため追従する。`json-path` だけは単一の
固定パスを直読みするため非追従:

| check           | `.gitignore` 追従 | `.gitignore` 対象パスの扱い               |
| --------------- | ----------------- | ----------------------------------------- |
| `file-exists`   | する              | **存在しない**扱い → ルールが違反を報告   |
| `file-absent`   | する              | **無い**扱い → ディスク上にあっても無検出 |
| `content-match` | する              | 走査対象外(対象0件は `info`)              |
| `max-lines`     | する              | 走査対象外                                |
| `frontmatter`   | する              | 走査対象外                                |
| `drift`         | する              | マスターとの比較対象外                    |
| `secret-scan`   | する              | 走査対象外                                |
| `json-path`     | **しない**        | 直読みのため従来どおり発火                |

ポリシーと突き合わせて確認したい影響:

- `secret-scan` は `.claude/settings.local.json` のような `.gitignore` 対象ファイルの値を
  報告しなくなる
- `file-exists` は `.gitignore` 対象のパスを「存在しない」と扱う。`.gitignore` 対象の
  ファイルを必須にしているルールがあれば error になるので、除外を外すかルールを見直す
- `file-absent` はその逆で、`.env` を `.gitignore` に入れていると baseline の
  `hygiene/no-env-file` が無検出になる。このルールは「`.env` をコミットさせない」ためのもので、
  `.gitignore` 対象ならコミットされ得ないため妥当だが、警告が消える点は把握しておく
- `json-path` を非追従にしているのは、`.claude/settings.json` をローカル管理している PJ でも
  `security/dangerous-permissions` を効かせ続けるため

- [ ] CLI が 0.4.0(`npx @guardsmith/cli version`)
- [ ] `guard lint` の結果が想定どおり

### 3. .gitignore に無いディレクトリは `ignore:` で除外する(任意)

`ignore` は全走査から除外する glob の配列。`rules` と違い extends 間で**連結**される
(重複は除去)ため、組織 overlay 側で足した除外を各 PJ が書き直す必要はない。

```yaml
version: 1
target: claude-code
extends:
  - github:novexar/guardsmith//presets/baseline.yaml@v0.5.2
ignore:
  - "vendor/**"
  - "**/__snapshots__/**"
rules: []
exemptions: []
```

`.gitignore` でカバーできないものだけを書く。`.gitignore` に入っているものは設定不要で除外される。

- [ ] 必要なら `ignore:` を追加した

### 4. エージェント worktree を持つリポジトリ

リポジトリ直下に各エージェントの worktree を置き、それぞれが `.venv` / `node_modules` を持つ
構成では、毎回それらが丸ごと走査され(数万ファイル)、`guard lint` が 1 分以上かかったり、
`secret-scan` が `.venv/Scripts/python.exe` 等を誤検知していた。

```
<repo>/
├── .gitignore            # `.claude/worktrees/` を含む
└── .claude/worktrees/
    ├── agent-a/          # リポジトリ全体のコピー + .venv / node_modules
    └── agent-b/
```

`.gitignore` にこの行があれば、0.4.0 は走査の時点で枝刈りする(ポリシーの変更は不要)。
worktree が `.gitignore` に**入っていない**場合は、ポリシーの `ignore` に追加する。

- [ ] `guard lint` が現実的な時間で終わる

### 5. 全走査が必要なとき: `--no-gitignore`

```bash
npx @guardsmith/cli lint --no-gitignore
npx @guardsmith/cli sync --no-gitignore
```

0.4.0 より前の挙動に戻し、`.gitignore` 対象のファイルも走査する。ローカル専用ファイルの
中身を点検する用途(例: `.claude/settings.local.json` に資格情報が入っていないかの確認)に使い、
常用はしない(遅く、誤検知も出るため)。ポリシーの `ignore` と `.git/` の除外は引き続き効く。

- [ ] 一度 `--no-gitignore` で点検した(任意)
