# v0.7.1 Migration Guide — incremental checklist for existing projects

**English** | [日本語](v0.7.1.ja.md)

Audience: projects operating on the v0.7.0 standards.
If you are migrating from an older version, apply the [v0.5.0](v0.5.0.md),
[v0.5.1](v0.5.1.md), [v0.5.2](v0.5.2.md), [v0.6.0](v0.6.0.md) and [v0.7.0](v0.7.0.md)
guides first, then continue with this guide.

> **First, the baseline**: remote references are tag-pinned, so **nothing breaks if you do
> nothing**. Catching up is optional.

**There is nothing to do on the project side.** v0.7.1 adds `guard bump <tag> --dry-run` to
the CLI and corrects the catch-up procedure in the documentation; the only change in the
standards themselves is the wording of the `init-project` skill.

## Checklist

### 1. Move the extends tag to `@v0.7.1` (optional)

```
guard bump v0.7.1 --dry-run   # dry-run: the plan and the predicted conflicts, writes nothing
guard bump v0.7.1             # applies it, and moves the extends tags and guardsmith.vars.yaml
```

The dry-run is the point of this release: it resolves the master at the **new** tag and
prints the plan the real run would apply, while writing nothing at all. `guard sync` without
`--write` is a dry-run too, but it measures against the tag your policy **currently** pins,
so it cannot predict a bump.

The standards' diff against v0.7.0 is limited to the `init-project` skill's wording, so
expect a single clean merge and no conflicts. Upgrade `@guardsmith/cli` to **0.6.1** first
if you want `--dry-run` (the v0.7.1 baseline itself still runs on 0.6.0).

- [ ] Reviewed the `guard bump v0.7.1 --dry-run` output
- [ ] Ran `guard bump v0.7.1`
- [ ] Verify: `npx @guardsmith/cli lint`
- [ ] Bumped the Action's `cli-version` / `release-tag` if you pin them

### 2. Rollback

Revert the `extends` tags in `guard.policy.yaml` to `@v0.7.0`, revert `standards:` in
`guardsmith.vars.yaml` (and the `CLAUDE.md` trailing stamp along with it — the two must
agree), and revert the merged file changes with git.

- [ ] Rollback steps shared with the team
