## v0.5.2 (2026-09-24)

A release that narrows what `guard lint` / `guard sync` walk to **files that could be
committed**. Repositories that keep large ignored trees under the repository root (agent
worktrees with their own `.venv` / `node_modules`) no longer pay for them on every run,
and `secret-scan` stops reporting files that never reach the repository. For the catch-up
steps for existing projects, see docs/migration/v0.5.2.md.

### Added

- Policy: a top-level `ignore` key (array of globs) excluded from every scan. Unlike
  `rules`, it is **concatenated** across `extends` layers (duplicates removed), so an
  organization overlay's exclusions reach every project
- `guard lint` / `guard sync`: `--no-gitignore` restores the full scan (same handling as
  `--no-cache`). The policy `ignore` and the `.git/` exclusion still apply
- `@guardsmith/core`: `runLint(policy, root, now?, { gitignore })` and
  `planSync(policy, root, { gitignore })`; the new `glob` module is exported

### Changed

- All file walking now honours `.gitignore` by default, including nested `.gitignore`
  files, and always excludes `.git/`. `secret-scan` therefore skips paths such as
  `.claude/settings.local.json`, and `file-exists` treats a `.gitignore`'d path as missing
- Ignored trees are **pruned during traversal**, not filtered afterwards. On a fixture with
  a 5,000-file fake `.venv`, walking `.claude/**` drops from 8.6 ms to 0.7 ms
- baseline `security/no-secrets-in-context`: added `!.claude/worktrees/**` to `paths`
  (matching presets/self.yaml) so agent worktrees are excluded on older CLIs too.
  The `ignore` key is deliberately **not** used in baseline — CLI 0.3.0 rejects unknown
  keys under its strict schema
- Bumped remote-reference tags and generated-artifact stamps to v0.5.2 (baseline drift
  source / policy generated by `guard new` / docs examples / the Action's `release-tag`
  default)
- npm: `@guardsmith/core` / `@guardsmith/cli` 0.4.0 (the Action's `cli-version` default is
  also 0.4.0)

## v0.5.1 (2026-09-16)

A release that systematizes commit/push prevention for GuardSmith runtime artifacts
(CI result JSON under `.guardsmith/`, `.claude/settings.local.json`). For the catch-up
steps for existing projects, see docs/migration/v0.5.1.md.

### Added

- New baseline rule: `hygiene/guardsmith-artifacts-ignored` (starts as warn).
  Checks that `.gitignore` contains exclusion lines for `.guardsmith/` and
  `.claude/settings.local.json` (the CI result JSON contains project-specific information
  such as repository name, branch names, and SHAs; settings.local.json contains hook
  URLs/tokens)
- `finish-task` skill: added a pre-commit check confirming that `.guardsmith/` /
  `.claude/settings.local.json` are not staged

### Changed

- standards/docs/CI_CD.md: explicitly documented that CI result JSON must never be
  committed/pushed to the repository
- Bumped remote-reference tags and generated-artifact stamps to v0.5.1 (baseline drift
  source / policy generated by `guard new` / docs examples / the Action's `release-tag`
  default)
- npm: `@guardsmith/core` / `@guardsmith/cli` stay bundled at 0.3.0 (0.3.0 had not been
  published, so the version is unchanged)

## v0.5.0 (2026-09-16)

A major overhaul of the standards (consolidating PRs #3–#7). The standards reference tag
(`STANDARDS_TAG`) is updated to v0.5.0. For the catch-up steps for existing projects, see
docs/migration/v0.5.0.md (tag pinning means nothing breaks if you do nothing; catching up
is optional and can be applied incrementally).

### Added

- **A: Frontend UI foundation standard**: adopted shadcn/ui + Tailwind + TanStack as the
  standard stack. New `presets/frontend.yaml` (only projects with a FE add it to
  `extends`; it is kept out of the baseline to avoid false warnings for BE-only
  projects). Details: standards/docs/FRONTEND_STANDARDS.md
- **C: ponytail adoption** (over-implementation restraint): `.claude/settings.json`
  auto-registers the marketplace, and `finish-task` runs `/ponytail-review` before its
  quality gate. Tests, input validation, security, and a11y are explicitly excluded from
  reduction
- **D: DESIGN.md practice**: added a design-spec template based on awesome-design-md-jp
  (including Japanese UI specs) to the standards. Concretized per project by init-project
- **F: standardized issue templates and an interface for external integrations**: three
  types — feature / bug / chore — with fixed headings (the old task.md is removed).
  Unified `start-task` branch naming as `<type>/<issue number>-<slug>` (a contract that
  lets external tools resolve the issue number from the branch name). Bundled an HTTP
  hooks sample (`.claude/settings.local.json.example`)
- New baseline rules: `agents/no-pinned-model` / `ci/no-remote-test-workflows`
  (both start as warn)

### Changed

- **B: CI/CD policy change**: day-to-day CI moves to local Docker (`make ci`), and GitHub
  Actions is reduced to deploy on main push only. CI result JSON is written to
  `.guardsmith/ci-results/` as the interface for external tools. GuardSmith itself keeps
  an External PR CI limited to fork PRs
- **E: model/effort policy for agents**: qa uses fable / effort high, implementation
  agents default to sonnet (docs/AGENTS.md). Hardcoded date-suffixed model IDs are warned
  by the baseline (`agents/no-pinned-model`)
- Bumped remote-reference tags and generated-artifact stamps to v0.5.0 (baseline drift
  source / policy generated by `guard new` / docs examples)
- npm: `@guardsmith/core` 0.3.0 / `@guardsmith/cli` 0.3.0 (the Action's `cli-version`
  default is also 0.3.0)

## @guardsmith/core 0.2.3 (2026-08-14)

### Fixed

- Projects scaffolded by `guard new` were missing `.gitignore` (#1). Cause: npm pack
  always excludes `.gitignore` from packages. Fixed by shipping it without the dot
  (`standards/gitignore`) via prepack and restoring it when `guard new` scaffolds.
  The GitHub Releases bundle path was never affected

## v0.4.0 (2026-08-14)

### Added

- **Single-bundle distribution via GitHub Releases**: a `guard.mjs` with all dependencies
  bundled, plus a presets/standards tar.gz, attached to each release. Environments that
  cannot reach the npm registry (air-gapped networks, egress restrictions) can use the CLI
  from GitHub alone (`node guard.mjs lint`)
- **Source selection for the Action**: new `source: npm | release` input (default npm).
  `release` uses the GitHub Releases bundle and runs without the npm registry
  (pin the tag with `release-tag`)
- Bundled bilingual (en/ja) READMEs in the npm packages (`@guardsmith/core` /
  `@guardsmith/cli` 0.2.2 — fixes the missing package description on npmjs.com)

### Changed

- Decoupled `guard new`'s reference tag from the npm version (`STANDARDS_TAG`). The
  reference tag is now bumped only in releases where the standards content changed
  (currently v0.2.1)

## v0.3.0 (2026-08-13)

### Changed

- Moved the GitHub Action to the repository root (`action.yml`), making it publishable to
  the Marketplace. Consumers switch to `uses: novexar/Guardsmith@v0.3.0` (the old
  `packages/action` is removed)
- Changed the Action's CLI acquisition from "repository checkout + pnpm install" to the
  npm-published `npx @guardsmith/cli` (version pinned via the `cli-version` input) — no
  setup needed and faster. The `guardsmith-ref` input is removed (replaced by
  `cli-version`)

The npm packages (@guardsmith/core / cli) stay at 0.2.1 (no changes to the CLI itself).

## v0.2.0 (2026-08-12)

### Added

- `github:` remote resolver: tag-pinned fetch for extends / drift source,
  `~/.guardsmith/cache` caching, `--no-cache`, private repository support via
  `GITHUB_TOKEN`, path-traversal hardening, multi-level extends resolution
  (3-layer overlay) with cycle detection
- `guard sync`: restore drifted files from the master (dry-run by default / `--write`,
  `allow_sections` preservation, missing-file creation)
- `guard new <dir>`: scaffold a new project from the full standards/ set
  (D-001: distribution unified on option A)
- GuardSmith Lint GitHub Action (`packages/action`): SARIF + Job Summary + PR comment
- npm-publishable packaging: `@guardsmith/core` (dist + bundled presets/standards),
  `@guardsmith/cli` (`guard` bin)
- README.en.md, SECURITY.md, issue templates

### Changed

- EOL-normalized drift / sync comparison (CRLF/LF differences are not treated as drift)
- Migrated to vitest (80% coverage gate), pnpm workspace, eslint + prettier, CI,
  self-application (presets/self.yaml)

### Fixed

- `guard init` referenced the non-existent `preset:novexar-baseline`
  (fixed to `preset:baseline`)
